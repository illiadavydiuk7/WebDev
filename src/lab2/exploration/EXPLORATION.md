# Дослідження
## 4.1. Box Model
Фактичні розміри блоків відрізняються через різний алгоритм розрахунку моделі коробки: у content-box властивості padding і border розширюють елемент назовні, а в border-box - включаються у фіксовані розміри блоку. Підхід box-sizing: border-box є значно більш передбачуваним для адаптивної верстки, оскільки запобігає неочікуваному розриву сітки та переповненню батьківських контейнерів при додаванні внутрішніх відступів і рамок.
## 4.2. Cascade
За однакової специфічності та однакового джерела пріоритет завжди має те CSS-правило, яке браузер прочитав останнім. Зміна черговості підключення файлів чи тегів `<style>` змінює фінальний переможець каскаду на користь найнижчого в документі.
## 4.3. Specificity
Вага селектора записується трьома числами (ID, Класи, Теги) - і браузер завжди порівнює їх зліва направо. Оскільки селектор #id має одиницю в найпершому розряді (1, 0, 0), він одразу перемагає будь-яку кількість класів на зразок (0, 5, 0) чи (0, 10, 0), бо класи не здатні «перестрибнути» у лівішу позицію й переважити ID.4.
## 4.4. Inheritance
Звичайний текст у `<p>` легко успадковує font-family та color від body, оскільки для типографіки в CSS успадкування увімкнене за замовчуванням. Натомість посилання `<a>` та кнопки `<button>` їх не успадковують, бо браузер має для них власні вшиті стилі (User-Agent Stylesheet) - зокрема свій колір, підкреслення чи системний шрифт, які мають вищий пріоритет за звичайне успадкування. Щоб змусити ці елементи перейняти стилі від батьківського блоку, для них явно прописують значення inherit (наприклад, font-family: inherit; color: inherit;).
## 4.5. CSS Variables
CSS-змінні успадковуються вниз по дереву DOM: якщо змінна оголошена в :root, вона діє глобально для всього документа, але при її повторному оголошенні всередині конкретного класу (наприклад, .dark-card) створюється локальний scope, де нове значення застосовується лише до цього елемента та його нащадків. Це дає змогу реалізувати темну тему чи акцентний стан картки, змінивши лише значення кількох змінних у батьківському класі, замість того щоб вручну переписувати стилі для кожного окремого внутрішнього елемента.
## 4.6. Повторне використання стилів і рефакторинг
Компонентний підхід дозволяє винести спільну логіку (розміри, геометрію, відступи) в один базовий клас на кшталт .btn, а за допомогою модифікаторів (.btn-primary, .btn-outline) описувати лише візуальні відмінності (кольори, рамки). Завдяки дотриманню принципу DRY (Don't Repeat Yourself) розмір CSS-файлу значно зменшується, оскільки однакові правила не дублюються під кожен елемент інтерфейсу. Підтримка такого коду стає набагато простішою та надійнішою: будь-які глобальні правки (наприклад, зміна базового радіуса скруглення чи висоти кнопок) вносяться лише в один селектор, автоматично оновлюючи всі елементи на сторінці без ризику пропустити окремий стиль.
